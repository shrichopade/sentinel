Prompt 1
Create backend/agents/guardrails.py
Full post-processing pipeline — 4 checks + apply_guardrails() entry point
Cursor prompt — paste into chat or cmd+k
Create the file backend/agents/guardrails.py for the sentinel.ai project. This file is a post-processing pipeline that runs on every agent output before it reaches the user or the actions table. It never blocks output — it annotates it with warnings. Implement the following four functions and a main entry point: 1. find_uncited_claims(text: str) -> list[str] Scan the text for sentences that make a factual claim (contains a number, a date, a vendor name, or a legal term) but do not include a citation marker in the format [N] or [Source]. Return a list of the offending sentences. 2. inject_legal_caveat(content: str, output_type: str) -> str If output_type is one of "risk_assessment", "letter_draft", or "legal_finding", append this exact string to the content on a new line: "\n\n---\nAI-generated summary. Review with a qualified professional before acting." Return the content unchanged for all other output types. 3. redact_pii(content: str) -> tuple[str, list[str]] Use regex to find and replace common UK personal identifiers: - National Insurance numbers (pattern: two letters, six digits, one letter — e.g. AB123456C) → replace with [REDACTED-NI] - Sort codes (pattern: XX-XX-XX where X is a digit) → replace with [REDACTED-SORT-CODE] - 8-digit strings that look like bank account numbers when near the word "account" → replace with [REDACTED-ACCOUNT] Return a tuple of (redacted_content, list_of_what_was_found). 4. check_scope_escalation(content: str) -> tuple[bool, str] Check the content for phrases that imply actions beyond the system's authority: "take legal action", "sue", "file a police report", "contact the Financial Ombudsman", "go to court", "file a claim", "seek legal counsel". If any are found, return (True, "This situation may require professional legal or financial advice."). Otherwise return (False, ""). 5. apply_guardrails(output: dict, output_type: str) -> dict Main entry point. The output dict always has a "content" field (string) and may have a "warnings" list (create it if absent). Run all four checks in sequence: - Citation check: if uncited claims found, append warning message and mark each offending sentence in the content with a ⚠ prefix. - Caveat injection: always run, replaces content in place. - PII redaction: if PII found, replace in content and append warning listing what was redacted. - Scope check: if escalation needed, set output["escalate"] = True and output["escalation_reason"] = the reason string. Return the modified output dict. Use only Python standard library (re, typing). No external dependencies. Add a LEGAL_CAVEAT constant at the top of the file holding the caveat string.
After running: Test by opening a Python shell in backend/ and calling apply_guardrails({"content": "The contract renews on 1 Jan 2026 and costs £50."}, "letter_draft"). Confirm the warnings list is not empty and the caveat appears at the bottom.

Prompt 3
Create backend/api/actions.py — all 6 HITL endpoints
GET list, GET detail, PUT approve/reject/edit, POST send
Cursor prompt
Create the file backend/api/actions.py for the sentinel.ai project. This file is a FastAPI router containing all six HITL action queue endpoints. Use the Supabase client from api.db (already exists at backend/api/db.py as "supabase"). Router setup: from fastapi import APIRouter, HTTPException from pydantic import BaseModel router = APIRouter(prefix="/actions", tags=["actions"]) Implement these six endpoints: 1. GET /actions Query the Supabase "actions" table for rows where status = "pending". Also join with the "documents" table to get vendor_name and doc_type for each action. Sort results: critical first, then high, medium, low. Return a list of summary objects (id, severity, title, summary, vendor_name, doc_type, created_at, escalate). Do NOT include draft_content in the list response. 2. GET /actions/{action_id} Return the full action row by UUID including: id, severity, title, summary, draft_content, reasoning, sources, warnings, escalate, escalation_reason, status, created_at. Also return vendor_name and doc_type from the joined documents table. Return 404 if not found. 3. PUT /actions/{action_id}/approve Set status = "approved" and actioned_at = now() on the actions row. Then call store_preference() from memory.long_term (create a stub if the module does not exist yet — just log the call for now). Return the updated action row. 4. PUT /actions/{action_id}/reject Accept an optional JSON body: {"reason": "string"}. Set status = "rejected" and actioned_at = now(). If a reason is provided, append it to the reasoning field. Call store_preference() stub. Return the updated action row. 5. PUT /actions/{action_id}/edit Accept JSON body: {"draft_content": "string"}. Update only the draft_content field. Status stays "pending". Return the updated action row. 6. POST /actions/{action_id}/send IMPORTANT SAFETY GATE: First check that the action's status is exactly "approved". If it is not, raise HTTPException(status_code=403, detail="Action must be approved before sending"). If approved, call send_letter() from api.email (create the module in the next step — for now import it and wrap the call in a try/except). On success: set status = "sent", actioned_at = now(). Return {"status": "sent", "action_id": action_id}. On failure: do NOT change the status. Return {"status": "error", "detail": str(error)}. Use async def for all endpoints. Import supabase from api.db. Add proper type hints throughout.
After running: Mount the router in main.py by adding: from api.actions import router as actions_router then app.include_router(actions_router). Restart the server and test GET /actions — it should return your Day 2 pending action.
